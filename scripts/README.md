# scripts/ · 可执行工具

**六个业务脚本**（下文表格前 6 行）纯标准库 Python、**无第三方依赖**，Windows/Linux/macOS 直接跑。另有四个**自检脚本**（不属于业务工具，改规则/改结构/改登记/改数字后必跑），以及**第 7 节的一份人工审计流程**（不是脚本）：

- `_redline_selftest.py` — `ledger redline` 的双向自测（99/99 + 12/12）
- `struct_check.py` — 骨架检查（编号连续 / 空章节 / 围栏成对 / 无 `\x08`）
- `_registry_check.py` — **登记一致性**（目录 vs `meta.assets`、声明项数 vs 表格行数、模块计数；rc 0/1/3）
- `_cross_check.py` — **公式三处一致**（模块正文 / 索引 / 脚本实跑，五组校对；rc 0/1/3）

```bash
python scripts/igbt_loss.py --help
```

|---|---|---|

## 1. `igbt_loss.py` — 损耗 / 结温 / 开关频率上限

**输入**：VDC、Ipk、调制系数 m、cosφ、fsw、VCE(sat) 线性化参数（VCE0 + rCE）、Eon/Eoff/Erec（含测试条件 Vref/Iref）、Tc、Rth(j-c)、Tjmax、并联数

**输出**：电流分量 → 通态/开关损耗 → Tvj → 余量 → **fsw 上限**

```bash
python scripts/igbt_loss.py \
  --vdc 800 --i-pk 400 --m 1.0 --cosphi 0.85 --fsw 8000 \
  --vce0 1.05 --rce 0.0032 --eon 45 --eoff 62 \
  --vref 600 --iref 400 \
  --tc 85 --rth-jc 0.12 --tmax 175
```

**关键说明**
- VCE0/rCE 必须用**工作温度（125℃ 或 150℃）**下的曲线拟合，不能用 25℃ 数据
- Eon/Eoff 按 VCC 与 IC **线性缩放**，未做 Rg/Lσ 修正——误差可达 30%+
- **开关损耗的电流口径系数 `--sw-factor`，默认 `1/π = 0.3183`**
  - 来源：书 p104 式 3.26 / p106 式 3.28–3.29，脚注「适用于正弦电流」。正弦电流下单个器件只在**半个工频周期**里有显著开关损耗，对整工频周期平均即得 `1/π`
  - **恒流 / 斩波 / 单脉冲工况传 `--sw-factor 1.0`**，否则会被默认值缩小 **π = 3.14 倍**
  - 输出里会打印 `（口径系数 = 0.3183，正弦 1/pi，书式3.29）`，JSON 里是 `inputs.sw_waveform_factor`
  - 反例：`worked-examples.md` **B⑧** 记录了漏掉这个系数导致 143.7 ℃ 被算成 224.9 ℃、结论从 PASS 翻成 FAIL 的全过程
- 返回码 1 表示热校核 FAIL（便于脚本串联）

## 2. `igbt_thermal.py` — 热阻链 / 瞬态 / 反解

三个子命令：

```bash
# (a) 热阻链拆解 —— 找瓶颈层
python scripts/igbt_thermal.py chain \
  --layer "die=0.01" --layer "die_attach=0.015" --layer "dcb=0.05" \
  --layer "baseplate_solder=0.02" --layer "baseplate=0.03" --layer "tim=0.025" \
  --ploss 300 --tcoolant 65 --tmax 175

# (b) Foster 网络瞬态热阻抗
python scripts/igbt_thermal.py zth --foster "0.008,0.002;0.03,0.05;0.06,0.6" \
  --ploss 300 --t 0.01

# (c) 反解所需总 Rth
python scripts/igbt_thermal.py require --ploss 300 --tc 85 --tmax 175 --safety 20
```

**为什么必须拆链**：`Rth(j-c)=0.12 K/W` 这种单一数字无法指导改进。要知道哪层贡献多少，才知道改哪层有收益。

**局限**：Foster 网络是数学拟合，**节点不对应物理层**；要把 Zth 映射到物理层需结构函数（专用设备与算法，如 T3Ster 体系）。

## 3. `igbt_life.py` — 雨流计数 / 寿命模型 / Miner 累积

### ★ 本脚本不内置任何"通用"寿命模型系数

Coffin-Manson 的 C、LESIT 的 A/Ea、Bayerer 的 K/β1..β6 都是**拟合参数**，随封装结构、材料、工艺、芯片厚度、键合线直径而变。写成"默认值"传下去是这个行业最常见的造假方式之一——换个封装能差一个数量级。

请用三种方式之一提供系数：
1. 从原始文献**抄录**（报告注明文献）
2. 用 `fit` 从**自有功率循环数据**拟合
3. 用 `--coef-file` 加载公司内部标定库

```bash
# (a) 雨流计数（注意 --min-range 滤噪）
python scripts/igbt_life.py cycles --csv mission.csv --col Tj --bin 10 --min-range 5

# (b) 单点预测
python scripts/igbt_life.py predict --model lesit --dtj 80 --tjm 125 \
  --coef A=1.77e12 --coef alpha=-4.8 --coef Ea=2.49e-20

# (c) 使命剖面累积损伤
python scripts/igbt_life.py stack --csv mission.csv --col Tj --bin 10 --min-range 5 \
  --model bayerer --coef-file my_coef.json \
  --ton 2.0 --wire-current 12 --vclass 1200 --wire-d 0.3

# (d) 用自有数据拟合 LESIT
python scripts/igbt_life.py fit --csv pctest.csv \
  --dtj-col dTj --tjm-col Tjm --nf-col Nf
```

**`--min-range` 必须用**：实测温度序列的测量噪声（±0.5K 甚至更大）会通过雨流算法产生成百上千个虚假小循环，淹没真实分布。建议取 **2–3 倍测量不确定度**。

**模型已知局限**
- Bayerer：不含基板焊层失效；不适用于牵引厚芯片
- LESIT：未分离键合线失效与焊层失效
- Coffin-Manson：忽略平均温度与时间效应

## 4. `aqg324_matrix.py` — 认证试验矩阵骨架

```bash
python scripts/aqg324_matrix.py --list
python scripts/aqg324_matrix.py --type module_si
python scripts/aqg324_matrix.py --type module_sic --format csv -o matrix.csv
python scripts/aqg324_matrix.py --type discrete_auto
```

支持 5 种产品类型：
| type | 对应 | 标准路线 |
|---|---|---|
| `module_si` | 硅基 IGBT 模组（车规） | AQG 324 04.1/2025 |
| `module_sic` | SiC 模组（车规） | AQG 324 + SiC 附录（DGS/DRB/dyn.H3TRB） |
| `module_ind` | 工业/牵引模组 | IEC 60749-34-1:2025 + 客户规范 |
| `discrete_auto` | 车规 IGBT 单管 | AEC-Q101 Rev E |
| `discrete_ind` | 工业 IGBT 单管 | IEC 60747-9:2019 |

**这是骨架，不是可执行计划。** 具体条件（温度/电压/循环数/样本量/判据）必须回标准正文或客户规范填写。CSV 输出预留了「具体条件/样本量/判据/责任人/状态」空列。

## 5. `igbt_book_budget.py` — 书源判据的可执行版

只实现《IGBT 模块：技术、驱动和应用》里**给出了完整式子**的五项预算，**外加 Baliga 层的两项查表**（降额四档谱 / SiC 打平门槛）。书没给式子的（`E_as`、缓冲电容设计式、驱动功率公式）**本脚本一律不提供**——那属于编。

```bash
# DESAT 时间预算（式 6.17；可选 6.19 风险上界）
python scripts/igbt_book_budget.py desat --cbl 100e-12 --uref 10 --idesat 250e-6 \
  --tsc 10e-6 --cd2 3e-12 --udelta 1100

# 短路能量上界（量级估算，不能用于定型）
python scripts/igbt_book_budget.py sc --udc 1100 --isc 4800 --tsc 10e-6 --tdetect 4.4e-6

# 端子电压 vs 芯片耐压（式 5.1）
python scripts/igbt_book_budget.py terminal --uces 1700 --lsig 20e-9 --didt 5e9 --u-bus 1100

# 低温工况：按书 p111 图 3.34 的降额比例再判一次（1.7 kV 器件冷启动）
python scripts/igbt_book_budget.py terminal --uces 1700 --lsig 30e-9 --didt 20e9 \
  --u-bus 1073 --temp-derate 12.3

# 并联降额（式 8.1）与线性化静态分流
python scripts/igbt_book_budget.py derate --n 2 --i-nom 1000 --i-tot 1756
python scripts/igbt_book_budget.py derate --i-tot 2000 --v0a 1.10 --v0b 1.10 --ra 0.00125 --rb 0.00170

# 死区时间（式 7.5）
# 死区（式 7.5，**两项都要**：IGBT 项 + 驱动传输延迟差项）
python scripts/igbt_book_budget.py deadtime --td-off-max 1.2e-6 --tf-max 0.2e-6 --td-on-min 0.6e-6 \
  --tphl-max 0.5e-6 --tplh-min 0.1e-6 --safety 1.5

# 书内例题自校：复现 p228 图 7.7 的 1.20 / 1.40 us
python scripts/igbt_book_budget.py deadtime --book-example 25
python scripts/igbt_book_budget.py deadtime --book-example 150

# 吸收电容（书 p347 式 13.9 量纲不成立 → 并列显示书印式与能量式）
python scripts/igbt_book_budget.py snubber --lsig 50e-9 --i-peak 1000 --uce-peak 1700 --udc 1100

# ── Baliga 层专项（v2.11.2 新增）────────────────────────────────
# 降额四档谱：只列表
python scripts/igbt_book_budget.py baliga-derate
# 400 V 母线 + 敏感负载（UPS）→ 需 800~880 V，建议取 900 V
python scripts/igbt_book_budget.py baliga-derate --constraint hard-emc --v-op 400
# 带拟选器件判定（低于下沿 rc=1）
python scripts/igbt_book_budget.py baliga-derate --constraint hard-emc --v-op 400 --v-rated 900

# SiC 成本打平门槛：复现书 p463 的 509 $/100 mm 片
python scripts/igbt_book_budget.py sic-parity
# 给定 SiC 晶圆价判定（<= 门槛 PASS，反之 rc=1）
python scripts/igbt_book_budget.py sic-parity --sic-wafer-price 480

# JSON 模式（写在子命令之前）
python scripts/igbt_book_budget.py --json terminal --uces 1700 --lsig 20e-9 --didt 5e9
```

| 子命令 | 依据 | 书页 | 返回码 1 的条件 |
|---|---|---|---|
| `desat` | 式 6.17 `t_bl=C_bl·U_ref/I_DESAT` | p189–190 | `t_bl + 内部处理 > t_SC` |
| `sc` | 式 7.6/7.7 的方向性依赖 | p105–107 | 保护动作时间已超过 `t_SC` |
| `terminal` | 式 5.1 `U_term=U_CES+Lσ·di/dt` | p142 | 母线 + 尖峰 > 芯片耐压（可用 `--temp-derate` 折算低温） |
| `derate` | 式 8.1 | p248–249 | 分流侧单管超额定 |
| `deadtime` | 式 7.5（IGBT 项 + 驱动延迟差项） | p228 图 7.7 | 算出 ≤0 或参数矛盾；**漏驱动项会低估 43~50 %** |
| `snubber` | **能量式 `C=L·I²/ΔU²`**（式 13.9 修正后）+ 式 13.10 | p346–348 | 不会 FAIL；`U_CE,peak ≤ U_DC` 时报错（无过压可言） |
| **`baliga-derate`** | **Baliga 降额四档谱**（★ **四档不是五档**） | Baliga p149/228/325/344 | 给定 `--v-rated` 时低于该档下沿 |
| **`sic-parity`** | Baliga 表 20.3 + A2.5 | Baliga p463 | 给定 `--sic-wafer-price` 时高于打平门槛（默认算得 **507 $**，书报 509 $） |

> **`baliga-derate` 的档位是「约束类型」不是「应用名」**：`clamp` 1.30× / `resonant` 1.60–1.70× / `hard-ctrl` 1.60–1.90× / `hard-emc` 2.00–2.20×。实测点 7 个（1.32 / 1.58 / 1.62 / 1.625 / 1.71 / 1.74 / 2.13）是**散点**，档间是插值建议，**不是书给的连续曲线** —— 别把中间值当书里的数引。
>
> **`sic-parity` 的两条独立路径必须都对上**：`21.548 × 0.5 × 78.54 × 0.60 = 507.7` 与 `3000 × 0.169 = 507.0`。若只有一条对上，说明输入参数混了口径（典型错误：把成本比 `12.18` 与售价比 `6.09` 混用）。

**四条使用边界**

- `deadtime` 的**驱动传输延迟差项**（`--tphl-max`/`--tplh-min`）不给就按 0 处理，会低估 43~50 %——脚本会打 `[WARN]`。书 p228 图 7.7 的算例里这一项占 **50 %**。
- `deadtime` 的 `--tr-max` 是**旧参数名且语义错误**（死区用下降时间 `t_f`，不是上升时间 `t_r`），仅为兼容保留；请用 `--tf-max`。
- `desat` 的内部分处理时间**书中未给数值**，必须由用户显式输入（默认 2 μs 仅为示例）。
- `desat --cd2/--udelta` 给的是**风险上界**（假设整个摆幅落在消隐窗口内），真实驱动会屏蔽瞬态，**不构成 FAIL**，只提示要实测波形。
- `sc` 是**上界粗估**（忽略 U_CEsat 与电流下降沿），只能判量级与"保护必须多快"，不能定型。
- `derate` 的 12 %/16 % 是书中特定算例（125 ℃、给定 U_CEsat 差），**不是通用降额系数**。
- `snubber` **并列显示书印式与能量式**，是为了让"差 1000 倍"这件事看得见；**只采用能量式**。它也不回答"该不该装吸收电容"——那个判断要看 `L_σ4 < L_σ1 + L_σ2` 是否成立，以及 p348 脚注②的寿命代价。

公式总索引见 `references/volke-hornkamp/34-formula-index.md`（含"哪些系数书没给"的清单）。

> **索引自身覆盖度（v2.7.0 实测）**：本表登记 **122 个式号**（区间行展开），38 个模块正文出现 **96 个**，并集 **139 个**、本表覆盖 **87.8 %**；逐章差口与唯一实质缺口（第 13 章 12 个式号，正文在模块 `39`/`22`）见 `34-formula-index.md §15.0`。**本表与模块冲突时以模块为准。**

## 6. `igbt_book_ledger.py` — 台账 / 区间 / 陷阱自检（v2.2 新增）

`igbt_book_budget.py` 只算"书里给了完整式子"的项；本脚本管另一类：**要记账的、带区间的、容易踩陷阱的**。

```bash
# ① Miner 线性累积（式 14.12）—— 多段周次 → 等效周次 → 小时 → 年
python scripts/igbt_book_ledger.py miner \
  --n 1.13e6 --n 4.11e6 --n 37.72e6 --n 0.36e6 \
  --dT 24 --dT 18 --dT 11 --dT 31 \
  --label 子周期1 --label 子周期2 --label 子周期3 --label 子周期4 \
  --t-cyc 300 --target-years 15

# ② CTE 失配 —— **强制声明取值口径**（p50 / table42 / fig147）
python scripts/igbt_book_ledger.py cte --a AlN --b Cu --source table42 --compare-to AlSiC

# ③ 热阻链（区分"自上而下"与"自下而上"两种口径）
#    1068 W 是 worked-examples 算例 B 修正后的总损耗（正弦口径 1/π，见下方 §2 的 --sw-factor）
python scripts/igbt_book_ledger.py rth --rjc 0.055 --rbase 0.013 --rtim 0.003 --rhs 0.038 \
  --ploss 1068 --tc 85 --tcoolant 65

# ④ 单位陷阱换算（书内 §13 八条）
python scripts/igbt_book_ledger.py unit --ohm-mm2-m 0.0264 --ppm-per-k 17 --mohm 3.2

# ⑤ 书未给红线自检：扫一份报告，看有没有把"书未给"当"书内数据"
python scripts/igbt_book_ledger.py redline --file my_report.md

# ⑥ AQG 324 试验台账骨架（条件留空，不代填）
python scripts/igbt_book_ledger.py aqg --list
python scripts/igbt_book_ledger.py aqg --type module_sic --n-sample 5 --format csv -o aqg.csv
```

| 子命令 | 关键设计 | 返回码 1 的条件 |
|---|---|---|
| `miner` | 输出**每段的损伤占比**，直接点出"靶心在哪一段" | — |
| `cte` | **不给 `--source` 直接报错**；有多个口径的材料会告警"书内有 N 个值" | — |
| `rth` | 两种口径同时打印，**明示不能混**；R_tim ≪ R_jc 时自动提示"换 TIM 救不了" | T_j 超 T_jmax |
| `unit` | 每个换算都附"陷阱说明" | — |
| `redline` | **12 条**"书未给 / 不可直接用"正则 + **12 条**"书内不一致"正则（含 3 条方向类） + 2 条归因错误正则（双向）+ **2 条式子误用正则（错式子 / 只引式号）** + **结构性缺项（死区式漏驱动项 / 误用 t_r）** + **Baliga 层专项 3 条（伪造出处 / 误乘 1/π / 跨层裸式号）**；另含**勘误豁免**与**登记表模式**（`--strict` 可关） | 命中任何一条（登记表模式下恒 0） |
| `aqg` | 只列试验项与 RQ/PQ 分组，**条件/判据全留空** | — |

> **v2.2.0 修的一处实质漏检**：初版只写了"出处在前"那一条。但中文报告里更常见的写法是**系数在前**（"c=3 取自《IGBT 模块》p383"），于是**最严重的一类错（把书未给的系数挂到书本出处上）恰好永远抓不到**。已改为双向。回归样例：
>
> | 输入 | 应否命中 |
> |---|---|

> | `Bayerer 模型的 beta1~beta4 按书 p382 取。` | ✅ 命中（系数在前 + 书 p） |

> **`redline` 的边界**：它是**字面**检查，不是语义检查。`c 取厂商标定值` 这种正确写法不报，但 `c 取 3`（不写出处）也不报——**不报不等于对**，它只兜"挂错出处"这一类最贵的错。

它抓的是**最严重的一类错误**——把书里**没给**的系数挂到书本出处上。本技能在 v1.x 曾出过这个错，现在由脚本守着。

> **v2.5.0 新增第 4 类：式子误用**（与前三类方向不同）。前三类管的是"这个数书上有没有"，这一类管的是**"书上这个式子本身对不对"**：
>
> ```
> (C_?S(nubber|n)?|缓冲电容|吸收电容)[^\n]{0,60}?[=＝≈≃][^\n]{0,25}?L[^\n]{0,20}?I_?peak\s*/
> (?<!不)(?<!不要)(?<!不能)(?<!不应)(?<!切勿)(?<!禁止)(按|依|用|采用|据)\s*式\s*13\.9
> ```
>
> 式 13.9（p347）分子缺一个 `I_peak`、量纲不成立（`(V·s/A)·A/V² = s/V ≠ F`），照抄结果**小 1000 倍**。
>
> **判别只靠一个记号**：错式里 `I_peak` 是**一次方且紧跟除号**（`I_peak/U²`）；正确式里 `I_peak` 后面是平方记号（`²` 或 `^2`），不紧跟 `/`。所以不需要去数上标——`I_peak\s*/` 本身就够。
>
> **第二行专门抓"只引式号、不写式子"**：这种情况无从复核，同样危险。前置否定 `(?<!不)…` 是为了把「**不要**用式 13.9」这类**警告句**和「按式 13.9 取值」这类**误用句**分开——两者只差两三个字，不区分的话，工具会把这本技能自己的忠告判成违规（v2.6.0 修）。
>
> 回归样例：
>
> | 输入 | 应否命中 |
> |---|---|
> | `吸收电容 C_Snubber = L_sigma * I_peak / (U_CE,peak - U_DC)^2 得 139 pF。` | ✅ 命中 |
> | `缓冲电容按式 13.9 取值。` | ✅ 命中 |
> | `吸收电容按能量式 C_Snubber = L*I^2/dU^2 算得 139 nF。` | ❌ 不命中（**正确写法**） |
> | `吸收电容最好直接安装在 IGBT 模块上。` | ❌ 不命中（无式子） |
> | `不要用式 13.9 算缓冲电容。` | ❌ 不命中（**警告句**，不是误用） |
> | `吸收电容按能量式算，不用式 13.9。` | ❌ 不命中（**警告句**） |
>
> **为什么单独列一类**：「书上没给」时人会去查厂商数据；「书上给了但错」时人会直接抄，还会标上"据《IGBT 模块》"——**后者更难被发现**。

> **v2.6.0 新增第 5 类：结构性缺项**（前四类都管"某个值/某个式子对不对"，这一类管**"这一项是不是漏了"**）。

>

## 7. 数值审计方法（v2.11.2 新增，**不是脚本，是流程**）

`redline` / `struct_check` 都只查**形态**：前者的判据是「字面上像不像违规句」，后者是「骨架完不完整」。它们**都查不出「结论改了但推导没改」**，也查不出「模块里声称登记了、索引表里其实没有」。本节的四个动作是这两类错的实际发现路径，值得每次大改后照做一遍。

### 7.1 动作一：偏差陈述回算（抓「数量级漏写」）

凡是正文里写了「差 N 倍 / 低估 N % / 高估 N 倍」，把**两个原值都打出来，除一遍**。

| 实例 | 正文原话 | 回算 | 判决 |
|---|---|---|---|
| `56 · A2.1` | 「结果 854，差 9.4 倍」（上一行算的是 `8.54×10⁵`） | `8.54e5 / 8000 = 106.8` | ❌ **107 倍**，漏两位数量级 |
| `58 · A2.1` | 「`1.258×10⁷` 与 `3×10⁵` 相差 42 倍」 | `1.258e7 / 3e5 = 41.93` | ✅ |
| `68 · A2` | 「`833 MW` 与 `11 MW` 差 76 倍」 | `833.33 / 11 = 75.76` | ✅ |
| `66 · A2.1` | 「书说 10 kΩ，实算 31 kΩ，差 3.1 倍」 | `31.11 / 10 = 3.111` | ✅ |

> **为什么这一类最值得查**：偏差倍数一旦算错，**定性判断会跟着错**。`56` 那条把「差 107 倍」写成「差 9.4 倍」，读者会以为「差不到一个数量级、可能是舍入」，而实际是「整个模型对不上、只能定方向」。

**顺带的收益**：反算常常能反推出书里的隐含假设。`58` 的 42 倍反解得 `ΔT = 60.2 K`，而 `2^5.36 = 41.9` —— 正好定量解释了该模块「式 6.1 比书报 MTTF 更陡」的结论。

### 7.2 动作二：禁用值裸用扫描（抓「登记了但当作结论用」）

### 7.4 动作四：撤销结论时重写推导链（**唯一必须靠人读的**）

`55 · A2.3` 是 v2.11.0 留下的**半修状态**：结论标了「已撤销」，但 `I.1` 的定义表和整段推导**仍按 `E_C²` 写**。

判据只有一条：**新的推导链必须自己算得出一个数，且这个数与另一处独立来源对得上**。

```
相对 BFOM = (E_C,SiC/E_C,Si)³ / [(ε_s,SiC/ε_s,Si)·(μ_n,SiC/μ_n,Si)]
         = 10³ / (0.83 × 0.64)
         = 1000 / 0.533
         = 1876            ← 与 72 · A2.4 自算的 1877 同源，差 0.05 %
```

若误用二次方：`10² / 0.533 = 188`，与书报「>2000」差 10.6 倍 —— **这正是 v2.11.0 之前误判「差 6 倍、量级不自洽」的来源**。改成三次方后偏差从 6 倍降到 6 %。

> **为什么检查器抓不到**：错的是**推理**，不是**字符串**。文中没有任何禁用的数字、没有任何挂错的出处，`redline` 全绿。这类错只能靠「改一个结论时，顺手把它的推导读一遍」。
