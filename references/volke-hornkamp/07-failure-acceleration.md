## R · 原文锚点

> 「应用工程师的一个主要任务是防止突发失效。在设计应用对象时必须考虑所有的相关因素防止出现失效。可以通过冗余系统，加强保护等措施来实现。……对于渐变失效，制造商起着决定性的作用，一旦确定器件的长期稳定性就不能改变。」【书 p366】

> 「图 14.2 概述了不同失效的机理，所有这些因素最终都可导致 IGBT 功率半导体的失效。灰色框表示突发失效的原因，阴影框表示可导致渐变失效的原因。」【书 p366】

> 「通常，可以通过例如温度、电压，或增加变化率来进行加速测试。根据测试目的的不同，比如针对不同的失效机理［式（14.6）和式（14.9）］，采用不同的加速模型。所有器件都需要进行工作点测试（称为'压力'测试），即设置测试工作点比其在实际应用的工作点（称为'OP'）高。」【书 p367】

> 「式（14.10）给出了测试周次和负载循环周次与温度波动 ΔT_Stress 和 ΔT_op 之间的函数关系。通过热循环测试可以评估系统焊接的可靠性。式（14.11）适用于功率循环测试以评估绑定线的可靠性。」【书 p370】

## I · 骨架一：失效率的四个口径（很多报告在这里混用）

四个指标量纲不同、用途不同，**混用是可靠性报告最常见的硬伤**。

| 指标 | 定义 | 书中的算例 | 用途 |
|---|---|---|---|
| **λ（失效率）** | λ = n /(N·Δt)（式 14.2） | N=8000 只、Δt=5000 h、n=4 只 → λ=1×10⁻⁷ h⁻¹ | 批量统计，与产量和观测时长绑定 |
| **FIT** | 1 FIT = 10⁻⁹ h⁻¹ | 上式 = 100 FIT | 系统级可靠性预算的基本单位 |
| **MTBF** | MTBF = 1 / Σλ（式 14.3） | 20 只@125FIT + 15 只@250FIT + 5 只@300FIT → **129 000 h** | 由器件 FIT **相加**推系统 MTBF |
| **ppm** | ppm = n_failed / n_delivered ×10⁶（式 14.4） | —— | 出厂质量，只有量产数据才算 |

**三个必须知道的限定（书里明写）**：
1. 系统 FIT 是**各组件 FIT 相加**，"如果没有其他冗余，复杂系统的 FIT 率由各个组件的 FIT 率相加得到"。
2. 「如果一个 IGBT 模块的 FIT 率为 100，其内部共有 24 个并联芯片，这样就可以计算出每个芯片的 FIT 率为 4.2。这并不是针对某一个特定的模块，而是在模块大量生产过程中的统计结果。」【书 p365】→ **模块 FIT 不能反推单管 FIT**，因为统计对象不同。
3. 「在计算 ppm 时，只有在规范操作过程中出现的失效才进行统计。样机、工程样品或其他样品都不在统计范围内。」【书 p365】→ 拿样机数据算 ppm 是无效的。

## I · 骨架二：两类失效与它们的责任划分

| | 突发失效 | 渐变失效 |
|---|---|---|
| 特征 | 自发、不可预知 | 可预测，随时间缓慢产生 |
| 典型触发 | 短路、过压、过温、驱动错误、ESD | 焊层疲劳、键合线疲劳、参数漂移 |
| **谁负责** | **应用工程师**（靠设计、保护、冗余） | **制造商**（靠材料与工艺的长期稳定性） |
| 书中的原话 | 「应用工程师的一个主要任务是防止突发失效」 | 「一旦确定器件的长期稳定性就不能改变」 |

> **这条划分的实战价值**：客户投诉时先判类别，再定责任方与整改路径。把渐变失效（焊层疲劳）当突发失效去查"哪一次过流烧的"，方向从一开始就错了。

## I · 骨架三：图 14.2 的失效机理树（这是 PFMEA 缺的那一层）

书的组织方式是**三段式**：`诱因 → 中间物理量 → 失效`。这个中间层是 PFMEA 里最容易漏掉的——它决定了你监控哪个参数能提前预警。

```
诱因（人/设计/环境）           中间物理量                终态
──────────────────────────────────────────────────────────
错误驱动失效 ─┐
控制软件逻辑失效 ─┼→ 短路故障 ──────────────┐
IGBT 选择错误 ───┘                          │
                                            │
过载 ────────────┐                          │
开关频率过高 ─────┤                          │
栅极电压过低 ─────┼→ 高损耗 ──┐              │
栅极电阻过大 ─────┘            │              │
                              ├→ 结温过高 ──┼→ 失效
高负载周次→焊层分离 ┐          │              │
安装错误 ──────────┼→ Rth(j-c)↑ ┤              │
散热不足 ──────────┴→ Rth(c-h)↑ ┘              │
                                            │
输出频率过低 ──────→ 结温波动增大 ───────────┤
电机加速过大 ──────→ 超过 2×Inom 峰值电流 ───┤
机械振动→绑定线断裂 ┐                        │
高负载周次→绑定线断裂┴→（开路，直接失效）    │
开关过快/高 di/dt ─┐                          │
杂散电感过大 ──────┴→ 集-射极电压过高 ───────┤
操作不当 ──────────→ ESD ────────────────────┘
UGE > UGE,max ─────→ 栅极电压过高（直通）
```

**怎么用这张树**（书没写，是工程用法）：
- **横向读**= 找监控点。`Rth(j-c)↑` 与 `结温波动增大` 是两个可在线监测的中间量，比直接等 `失效` 早得多。
- **纵向读**= 找设计冗余。`散热不足` 与 `安装错误` 都指向 `Rth(c-h)↑`——所以**同一个热阻上涨，可能是设计问题，也可能是产线装配问题**，必须分开验证。
- **反查读**= 从失效现象反推。`VCEsat 涨但 Rth 不变` → 走绑定线分支；`Rth 涨而 VCEsat 变化小` → 走焊层分支（与 playbook 第 4 条一致）。

> ⚠ 图 14.2 是灰/阴影双色标注（突发/渐变），扫描件色彩分离度低，**逐框归类有读图误差**。上面只保留拓扑关系，不给每框贴类别标签。

## I · 骨架四：四个加速模型（式 14.5–14.9）

前置定义：**加速因子 AF = t_op / t_stress**（式 14.5）——即"现场跑 1 小时等于台架跑几小时"。

| 模型 | 表达式 | 加速什么 | IGBT 里用在哪 |
|---|---|---|---|
| **Arrhenius（阿氏）** | AF = exp[ γ·(1/T_op − 1/T_stress) ]（14.6） | 温度（化学反应速率） | 长期高温存储、HTRB 类 |
| **Eyring（艾林）** | AF(U,T) = AF(T) · exp[ B·(U_stress − U_op) ]（14.7） | 温度 + 电压（电场加速） | 电压加速的绝缘/钝化退化 |
| **Peck（佩克）** | AF(RH,T) = AF(T) · (RH_stress/RH_op)^n（14.8） | 温度 + 湿度 | **H3TRB / 85-85** |
| **Coffin-Manson（科芬-曼森）** | AF(ΔT) = (ΔT_stress/ΔT_op)^c（14.9） | 温度摆幅（热机械疲劳） | **TC / 系统焊层** |

**四个模型的边界（书里给了脚注，这是关键）**：
- Arrhenius 是 Svante Arrhenius **1889 年**从反应速率导出的，γ 与"测试中的活化能"有关；
- Peck 里 n 是"与被研究的失效机理相关的因子"，**不是常数**；
- Coffin-Manson 里 c 是"疲劳延性系数，是材料的固有特性"——**换材料 c 就变**。

> **这条直接支持本技能的立场**：`igbt_life.py` 不内置任何系数，因为 c、γ、n、β 全是**拟合参数而非物理常数**。书在 14.3 末尾也明说：「对于式（14.10）和式（14.11）中的参数 β1~β4，不同的制造商给出的数值各不相同……需从制造商那里了解到正确的或推荐的参数值。」

## A1 · 完整算例：15 年 / 12397 周次（图 14.5）

这是书中第二个完整算例（第一个是 05 号文件里的 21167 h），**口径不同，不要混用**。

**输入**（图上直接标注）：
- 寿命 15 年，每天 2 个负载周次
- t_on,Stress = 2 s，I_Stress = 400 A
- ΔT_Stress = 100 K，T_j,min,Stress = −50 ℃
- 输出：**需要 12397 个周次表示应用对象的负载情况**

**推导链**（图 14.3 的流程，按箭头走）：

```
器件电气参数(UCEsat,UF,Eon,Eoff,Erec) ┐
电机与驱动控制参数(U DC,Iload,cosφ,fsw)┼→ 损耗计算 → 损耗曲线
负载曲线                              ┘        │
                                               ↓（叠加 Zth(j-c),Zth(c-h),Zth(h-a)）
气候条件 Ta ────────────────────────→ 热计算 → 热曲线
                                               ↓
                                    温度波动计算 ΔT_op
                                               ↓
                              不同温度波动 ΔT_op 的计数（直方图）
                                               ↓
                                    寿命模型（式 14.10）
                                               ↓
                            确定一个 ΔT_Stress 代替所有 ΔT_op 所需周次
```

**两处只有看图才能拿到的细节**：
1. **温度要分三条算，不能只算一条**：图 14.4a 的图例是 `T_op,Junction/Bondwire`、`T_op,Diode`、`T_op,Solder` 三条曲线。正文明确：**结温波动用于评估绑定线的连接可靠性；子系统下焊层温度用于评估基板和 DCB 之间焊接连接的可靠性**【书 p368】。
2. **直方图不是装饰**：图 14.4b 是"在给定温度波动 ΔT_op 下的负载周次测试次数"分布，横轴 ΔT_op 0–70 K，纵轴 0–100 次。**寿命计算要喂的是这个分布，不是平均值。**

> **这就是"寿命数字不带条件就是噪声"的操作版**：同一份现场数据，先把 ΔT 拆成分布（几十个 bin），再用模型逐个折算，最后合成一个等效 ΔT_Stress。整个链条里任何一步用"平均 ΔT"替代，结果就废了。

## E · 触发场景

- 「客户要 MTBF，供应商给的是 FIT」→ MTBF = 1/Σλ，先确认系统内所有组件的 FIT 是否同口径（模块级 vs 芯片级）
- 「8000 只跑了 5000 h 坏 4 只，失效率多少？」→ λ=1e-7/h = 100 FIT；注意这是**统计值，不是单只的预测寿命**
- 「样品阶段 ppm 是 0，能不能写进报告？」→ 不能，ppm 只统计量产规范操作中的失效
- 「H3TRB 的加速因子怎么算？」→ Peck，但 n 随机理变，必须用自有数据拟合
- 「客户问为什么焊层疲劳不算突发失效」→ 渐变失效，责任在制造商一侧的材料与工艺
- 「同一个 Rth 上涨，是设计散热不足还是装配不良？」→ 图 14.2 里两条支路都指向 Rth(c-h)↑，必须分开验证

## S · 步骤（做一次规范的加速试验设计）

1. **定失效机理**：先在图 14.2 上定位要考核的中间物理量（结温过高 / 电压过高 / 热阻增大 / 电流超限）
2. **选模型**：热机械疲劳 → Coffin-Manson；湿度 → Peck；电场 → Eyring；纯热老化 → Arrhenius
3. **取系数**：向制造商索取 β1~β4 / c / γ / n，或用自己的试验数据拟合（`scripts/igbt_life.py fit`）
4. **算 AF**：AF = (ΔT_stress/ΔT_op)^c（或对应模型），得到"1 h 台架 = AF h 现场"
5. **定样本量与判据**：判据必须与试验类型匹配（PC 看 VCEsat 5%，TC 看 Rth/分层）
6. **反算**：台架周次 × AF ÷ 年循环数 = 等效年数，与目标寿命比
7. **写清口径**：脉冲/非脉冲、ΔT 定义（ΔTj 还是 ΔTc）、判据阈值、样本量——**这四项缺一项，数字不可比**
