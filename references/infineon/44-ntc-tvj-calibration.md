# 44 · NTC 测结温与 Tvj 的真实身份：`virtual` 结温与「没有通用关联模型」

> 来源：`075` 论文｜如何通过 IGBT 模块内置的 NTC 电阻测量芯片结温、`083` Tvj —— IGBT 元宇宙中的结温、`061` IGBT 短路结温和次数（部分交叉）。
>
> **层归属**：厂商层。书源 `15-thermal-model-heatsink` 与 `10-measurement` 已讲 TSEP 校准（`I_ref ≈ I_nom/1000`、小电流下负温度系数）与四种测温方法，但**没有回答「Tvj 到底是谁的温度」**，也没有 NTC 与芯片温度的标定方法。本模块补这两块。

## R · 原文锚点

> 「在 IGBT 器件 datasheet 里的结温代号是 Tvj，这里的「v」是什么意思？其实 v 是指 virtual，Tvj 就是 virtual junction temperature——虚拟的结温。」【`083`】

> 「此时 IGBT 模块的 Tvj 就是 120℃，因为它表征温度的 Vcesat=0.5V，和芯片在理想均匀的 120℃ 时 Vcesat 测试值相同。但其实真实的芯片结温可能中间这片表面中心位置 125℃，绑定线 130℃，而边上的芯片表面只有 110℃。」【`083`】

> 「IGBT 模块的 Foster Zth 模型就是在元宇宙中的热模型，Tvj 就是基于 Zth 热模型推导出来的温度。」【`083`】

> 「对于内置 NTC 电阻的功率模块来说，芯片和 NTC 电阻之间**没有通用的关联模型**（热阻或者温度关系）。在特定的系统中进行热测试，是精确获得两者相互关系的必然手段。」【`075`】

> 「NTC 电阻需要较长的时间才能响应系统负载工况变化，所以用它来监控系统的瞬态工况是不可能的。」【`075`】

## I · 骨架

### 骨架一：Tvj 的定义——它不是「最高点温度」，是「等效均匀温度」

**常见误解**（原文引自百度百科/维基）：「结温就是芯片内部最高点的温度」。

**真实定义**：

```
Tvj = 使得 V_CEsat(I_ref) 恰好等于实测值的那个【等效均匀温度】
```

**`083` 的标定链条（这是理解 Tvj 的唯一入口）**：

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 把模块放进温箱，**均匀加热到 120 ℃**，等热平衡 | 此时模块内所有芯片与部件温度**完全一致**，可认为结温就是 120 ℃ |
| 2 | 在此状态下通 `I_ref`，测 `V_CEsat` | 例如得 **0.5 V** |
| 3 | 把模块装到散热器上，通几百安培直流加热 | 内部并联芯片温度**并不一致** |
| 4 | 再测 `V_CEsat(I_ref)`，读数**恰好也是 0.5 V** | → **Tvj = 120 ℃** |

**但真实分布是**：

| 位置 | 真实温度 |
|---|---|
| 芯片表面中心 | 125 ℃ |
| 绑定线 | **130 ℃** |
| 边上芯片表面 | 110 ℃ |
| **Tvj（标称）** | **120 ℃** |

> **这是本模块最重要的一句话**：`Tvj` 是一个**通过 `V_CEsat(I_ref)` 反推的等效常温**，用它代替整个模块的温度状态。它能保证「用这个温度查 datasheet 得到的 `V_CEsat` 与实际相符」，但**不能保证局部最高温不超过它**——绑定线比 Tvj 高 10 ℃ 是常态。

**为什么必须这样定义**：芯片温度不均匀（中高周低）、绑定线温度比芯片表面更高、且**绑定线与芯片表面的温差随电流增大而升高**；同时芯片被封装包裹，红外测不到、热电偶贴在芯片不同位置读数不同、粘接紧密程度还影响结果。→ **没有任何物理手段能直接测到「最高点」**，只能定义一个虚拟量。

### 骨架二：Tvj 的三条推导路径（必须分清在哪一层）

| 层级 | 怎么得到 Tvj | 用途 | 精度 |
|---|---|---|---|
| **物理标定** | 温箱均匀加热 → 测 `V_CEsat(I_ref)` → 描出 `Tvj–V_CEsat` 线 | 建立热阻测试的基准 | 最高（但只在实验室） |
| **`Z_th` 模型** | 实测基准温度（如进风口）+ `P·Z_th(t)` | 工程计算、寿命预测 | 取决于 `Z_th` 是否被测系统 |
| **NTC 查表** | 读 NTC 电阻 → 查本系统实测的 `T_chip = f(R_NTC)` | **运行中的过载保护** | 取决于标定质量 |

**第 3 条是 `075` 的主题，也是坑最多的一条**（见骨架三）。

### 骨架三：NTC 标定——为什么「没有通用关联模型」

**`075` 的核心结论（必须在引用时保留原话）**：

> 「芯片和 NTC 电阻之间**没有通用的关联模型**（热阻或者温度关系）。在特定的系统中进行热测试，是精确获得两者相互关系的**必然手段**。」

**这意味着**：不能拿某篇论文或某家 datasheet 的 `T_NTC → T_chip` 关系直接套到自己的系统上。**必须在自己系统上实测一遍。**

**标定方法（`075` 的完整流程）**：

1. 被测器件（例：FF1000R17IE4，1000 A / 1700 V）固定在**风冷散热器**上，风速可调，**保证与实际系统工况相同**
2. 用**直流源**加热（例：只加热二极管芯片）→ 芯片产生压降与损耗
3. 芯片温度用**红外热像仪**测；基板壳温用贴在基板上的**热电偶**测
4. NTC 电阻值由数据采集器记录，按 datasheet 的电阻-温度曲线换算成温度
5. 调到不同加热功率 → 待**温度稳定**后记录 → 得到 `T_diode = f(R_NTC)`
6. **用 3 次多项式插值**才能准确描述这条非线性曲线
7. 用 `T_NTC` 替换 `R_NTC` → 得到 `T_diode = f(T_NTC)`（此时是**线性**关系）

**三条会踩的坑**：

| 坑 | 表现 | 原因 |
|---|---|---|
| **① 冷却方式改变耦合** | 水冷系统下芯片与 NTC 的**温差增大** | 风冷时热量在基板/散热器上**横向传播**，能充分加热 NTC；水冷时横向扩散弱 → 热耦合减弱 |
| **② 稳态 vs 瞬态** | 只能用于稳态/缓变 | 强迫风冷热时间常数**几分钟**；水冷 **30–60 s**。NTC 响应慢，**不可能监控瞬态** |
| **③ 直流加热忽略芯片间耦合** | 模型偏保守或偏乐观 | 单一芯片加热忽略了芯片间热耦合；可用**交流源**替代直流源改善（参考文献[5]） |

> **②的正反两面**：NTC 不能做瞬态保护，但**恰好适合做过载保护**——因为常见的过载（散热器腐蚀、风扇故障、水泵损坏）都是**逐渐加剧**的，NTC 有足够响应时间。

### 骨架四：「最热点」与「Tvj,max」不是一回事——红外数据会偏保守

`075` 的量化对比（单个芯片，同一工况）：

| 测量口径 | 温度 |
|---|---|
| 红外看到的**最高点（在绑定线上）** | **104 ℃** |
| 芯片表面最高温 | 约 **100 ℃** |
| 芯片表面**平均**温度 | **93 ℃** |

**三个数字差 11 ℃，口径完全不同**：

- **标准 in-situ 方法**：考虑模块内**所有芯片**，得到的是**芯片最大平均温度** → 用于预测 PC 寿命（引 AN2010-02）
- **红外最热点**：得到的是**局部极值** → 用它建热模型**相当保守**

> **规则**：若要用红外数据替代 in-situ 数据建热模型，**必须对所有发热芯片仔细分析并取平均**，否则模型会过度保守（→ 算出来的寿命偏短、选型偏大）。

## A1 · 案例：`083` 的热阻测试台测的是什么

`083` 给出的标准瞬态热阻测试流程，与 `075` 是两个不同实验：

| 项目 | `083`（热阻测试台） | `075`（NTC 标定） |
|---|---|---|
| 目的 | 测 `Z_th` | 测 `T_chip = f(T_NTC)` |
| 加热源 | **大电流源**（与 `I_Cnom` 同数量级） | 直流/交流源（可只加热一种芯片） |
| 测量 | **`I_ref` 小电流**（`≈ I_nom/1000`） | 红外热像仪 + NTC + 热电偶 |
| 时序 | `t = 0` 切断加热电流，`I_ref` 继续流通 → 记录 `V_CEsat` 衰减 | 稳态，等温度平衡 |
| 产出 | `Z_th(t)`（常用 **Foster** 表示） | `T_diode = f(R_NTC)` 多项式 |

**`083` 的关键说明**：`Z_th` 也可由**结构函数**推导（见 **JESD51-14**）——这与 `46-thermal-model-boundary` 的 Foster/Cauer 讨论是同一体系。

**`083` 的诚实提示**：「英飞凌在标定 IGBT 模块安全工作区时已经留了足够的裕量，所以客户只需要关心 Tvj 有没有超过上限就可以了」——**这是厂商对 Tvj 虚拟性的兜底承诺**，但也意味着：**若你做的是定制封装/自研模块，这个裕量不一定还在**。

## A2 · 本地复算：温度口径差异

```python
# 075 的三个温度口径
wire_max, chip_max, chip_avg = 104, 100, 93
print('绑定线最热 vs 芯片平均 =', wire_max - chip_avg, 'K')
print('芯片表面最高 vs 平均  =', chip_max - chip_avg, 'K')
print('红外最热点相对 in-situ 平均的偏差 =',
      round((wire_max - chip_avg) / chip_avg * 100, 1), '%')

# 反推：若按 104C 设计而实际 in-situ 只到 93C，有多少"白留"的余量
print('若 Tvj,max=150C，保守口径会少用', round((150-104)-(150-93), 0), 'K 的可用温升')
```

```
绑定线最热 vs 芯片平均 = 11 K
芯片表面最高 vs 平均  = 7 K
红外最热点相对 in-situ 平均的偏差 = 11.8 %
芯片表面最高 vs 平均 = 7 K
若 Tvj,max=150C，保守口径会少用 11 K 的可用温升
```

**判读**：用「红外最热点」建模型，相对 in-situ 平均口径**白扔 11 K 的可用温升**。按 `15-thermal-model-heatsink` 的散热器 `f` 修正因子（0→2 m/s 能买 108 K），11 K 大致相当于**多花一档风速**——所以口径错会真金白银地多买散热。

## E · 触发场景

- 「NTC 读数能直接当结温用吗？」→ 不能。**没有通用关联模型**，必须在本系统实测 `T_chip = f(T_NTC)`
- 「为什么水冷系统 NTC 跟结温差得更多？」→ 水冷下基板横向扩散弱，NTC 与芯片热耦合减弱
- 「能不能用 NTC 做过流保护？」→ **不能做瞬态**（响应 30–60 s 起步），**可以做缓变过载**（风扇故障/水泵损坏）
- 「红外测到的最热点是不是就是 Tvj？」→ 不是。Tvj 是等效均匀温度，最热点是局部极值，差约 11 K（`075` 实测）
- 「Tvj 到底是谁的温度？」→ 「virtual junction temperature」，由 `V_CEsat(I_ref)` 反推的**等效**温度，不是最高点
- 「绑定线温度能比 Tvj 高多少？」→ `083` 例子里高 **10 K**，且随电流增大而增大

## S · 步骤

**A. 做 NTC 过载保护标定**

1. 把模块装到**与实际系统相同**的散热器/风速/水温上
2. 用可调加热源（直流或交流，后者含芯片间耦合更真实）逐档加热
3. 每档**等热平衡**后同时记录：NTC 电阻值、芯片温度（红外）、壳温（热电偶）
4. 拟合 `T_chip = f(R_NTC)`，**非线性段用 3 次多项式**
5. 再把 `R_NTC` 按 datasheet 换算成 `T_NTC`，得到线性关系 `T_chip = f(T_NTC)`
6. 按目标 `Tvj,max` 反推 NTC 触发值，留出**绑定线比芯片高约 10 K** 的余量

**B. 核对热模型口径**

7. 明确自己的 `Tvj` 是哪个口径：in-situ 平均 / 红外最热点 / `Z_th` 推算
8. 若用红外数据，**必须取所有发热芯片的平均**后再建模型

## B · 边界

- **NTC 与芯片之间没有通用关联模型**（`075` 原话）→ 本模块**故意不提供**任何 `T_chip = f(T_NTC)` 的通用公式。给了就是编造
- **`075` 的 104/100/93 ℃ 是 FF1000R17IE4 在特定风冷试验台、单加热二极管芯片下的数据**，不能外推到其它模块/封装
- **`075` 的所有数据均在热稳定后测量**，忽略了热容影响 → **仅在稳态工况有效**。原文明确「用它来监控系统的瞬态工况是不可能的」
- **`075` 的标定用直流源加热，忽略了芯片间热耦合** → 模型有已知偏差；原文建议用交流源改善
- **Tvj 的虚拟性有厂商裕量兜底**：「英飞凌在标定 SOA 时已经留了足够裕量」——但这是**对英飞凌自家模块成立**。自研封装、二次封装、换 TIM 之后，这个裕量不能默认继承
- **`Z_th` 的 Foster 参数不代表物理结构**：`083` 用 Foster 只是为了数学表达方便；物理可解释性与唯一性问题见 `46-thermal-model-boundary`
- **`061` 的短路温度（360/461 ℃、电流丝 367 ℃）是仿真值**，不是实测；短路结温不能作为 Tvj 判据使用，短路是独立工况
- **不覆盖「片上集成温度传感器」**：语料中未给这类器件的标定方法
